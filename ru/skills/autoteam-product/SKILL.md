# Продукт из идеи

Не пишешь код и не выбираешь стек. Кому какая польза и что не делаем. Валидация — петля, не разовый шаг: обратная связь и цифры возвращаются сюда и меняют картину.

**Вход.** Идея, рынок, хотелка; позже — цифры (`autoteam-analytics`) и обратная связь пользователей. **Выход.** Картина продукта, in/out, вопросы с полем Ответ, дешёвые тесты спроса до кода. **Запреты.** Код; обещать рынок без evidence; канцелярит вместо имени. **Evidence.** Факт vs заявление vs ASSUMP раздельно. **Стоп.** Только Blocker для всей поставки (деньги/право/две трактовки ценности). Иначе ASSUMP и параллельно черновик spec. **Дальше.** Кому и против чего → `autoteam-positioning`. Spec → `autoteam-requirements`. Объём → `autoteam-scope`. Тест спроса как эксперимент → `autoteam-research`.

Порядок: кто страдает (1–2 роли) → результат в жизни → картина «как могло бы» (предложение) → in/out → сценарии → риски чужих систем → Q-* с полем Ответ → дешёвый тест спроса до кода, где возможно (лендинг с оффером, интервью, прототип).

Петля после запуска: цифры активации/удержания и слова пользователей → пересмотр картины и in/out. Провал активации — сигнал сюда и в `autoteam-positioning`, не только в UI.

Артефакты в **текущем** репозитории: `docs/product/problem.md`, `proposal.md`, `open-questions.md`.

Порядок величины экономики на старте: `docs/product/unit-economics.md` канона. Живую экономику ведёт `autoteam-pricing`. Домен: `docs/product/domains.md`.

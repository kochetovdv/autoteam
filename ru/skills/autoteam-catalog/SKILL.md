# Каталог autoteam

Канон метода — этот набор скиллов (репозиторий autoteam: `skills/`, `docs/`, `templates/`). Рабочие копии могут лежать в каталоге скиллов любой агентной среды. Расхождение с каноном — ошибка: править канон, затем копировать.

Пути `docs/` и `templates/` ниже — канон метода, если репозиторий autoteam доступен. Артефакты продукта — в текущем репозитории. Если канон недоступен, достаточно `SKILL.md` выбранного скилла.

**Вход.** Ситуация, есть ли ТЗ/репо/стек. **Выход.** Один skill или цепочка и почему. **Запреты.** Не делать работу за другие скиллы; не назначать стек. **Стоп.** Нет. **Дальше.** Выбранный skill. Неизвестный репо → сначала `autoteam-onboarding`.

## Эталон (все скиллы)

1. Автономия: одно поручение → работа до настоящего стопа. Стоп: деньги, право, безопасность, необратимое, две трактовки контракта. Не спрашивать на каждом шаге. Режим «решение» («сделай рабочее решение») — вопросы становятся журналом решений, стопы только жёсткие: `autoteam-orchestrator`.
2. Стек: текущий репозиторий / ADR. Нет стека — вопрос человеку, не выдумывать. `docs/process/stack.md`.
3. Метод, не макет заказчика. Шаблон выхода — только если он уже есть в продукте.
4. Согласование не стопает независимые задачи (`Blocked` vs можно продолжать).
5. Приёмка кода — другой агент и другая семья моделей. Секреты не читать.
6. Неизвестный репо — `autoteam-onboarding`. Каденс ревью устройства — `autoteam-architecture-review`, не блокируя чужой поток.
7. Язык отчётов и вопросов — язык человека проекта (по умолчанию язык поручения); термин с пояснением. Код и имена API не переводи.
8. Evidence симметричен: утверждение об отсутствии («нет X», «нельзя Y») требует команды проверки так же, как утверждение о наличии. Отсутствие наблюдения ≠ наблюдение отсутствия; сбой среды фиксируется как сбой среды. Вывод об отсутствии допустим только с областью поиска: «не найдено» без «искал в: X» — дефект формулировки, проверяющий обязан вернуть.

Проектный overlay (конфиг-каталог среды в репозитории продукта: пути, шаблон выхода) не переписывает метод.

## Ситуация → skill

| Ситуация | Skill |
|----------|--------|
| Неясно / несколько работ | `autoteam-orchestrator` |
| Новый репозиторий | `autoteam-onboarding` |
| Идея без ТЗ | `autoteam-product` |
| Кому и против чего продаём, оффер, нейминг | `autoteam-positioning` |
| Тарифы, цена, платежи, окупаемость | `autoteam-pricing` |
| Затраты, лимиты, ROI трат | `autoteam-budget` |
| Что меряем, воронка, дашборд | `autoteam-analytics` |
| Каналы, конверсия, удержание, SEO/GEO | `autoteam-growth` |
| Статьи, посты, письма, тексты | `autoteam-content` |
| ТЗ / spec | `autoteam-requirements` |
| Объём, пробелы входа, порядок MVP | `autoteam-scope` |
| Устройство системы, ADR | `autoteam-architecture` |
| Каденс / срочное ревью устройства | `autoteam-architecture-review` |
| Фича, баг, контракт, QA | `autoteam-delivery` |
| Гонки, отказы, производительность | `autoteam-quality` |
| Секреты, сессия, угрозы, роли, ПДн | `autoteam-security` |
| UI первоклассный | `autoteam-ui` |
| Презентация, таблица, текст | `autoteam-documents` |
| Документация бизнеса и кода, каденс | `autoteam-docs` |
| Выкатка, среды, инцидент | `autoteam-release` |
| Эксперимент, спайк, feasibility | `autoteam-research` |
| Разбор прогона, правки метода | `autoteam-retro` |

Цепочка «идея → деньги»: `product` → `positioning` → `requirements`/`scope` → `architecture` → `delivery` (+`quality`/`security`/`ui`) → `release` → `analytics` → `growth`/`content` → `pricing`/`budget`. Оркестратор ведёт, стадии итерируются, не водопад.

Домены: метод в каноне `docs/product/domains.md`, не отдельный skill на отрасль.

Чего нет: канон `docs/process/gaps.md`.

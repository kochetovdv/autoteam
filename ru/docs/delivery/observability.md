# Наблюдаемость

Когда обязательно (иначе выкатка L2+ с отказом «не видим»):

- входящий запрос имеет id, который виден в логе API и по возможности в UI ошибки;
- ошибка 5xx и таймаут исходящего вызова пишутся с кодом и сущностью, без секретов;
- для фона: «жив ли worker», последняя успешная работа, застревание очереди.

Метрики: латентность, ошибки, насыщение очереди/пула. Трассировка между процессами — если запрос прыгает API→worker→БД и без этого не чинят инцидент.

Дашборд и алерты — по продукту; минимум — grep по `request_id` в runbook.

# Проверки качества (QA)

TDD — сначала падающая проверка, потом код. Это не замена пирамиды.

| Вид | Когда обязателен | Когда N/A |
|-----|------------------|-----------|
| Unit | правила, расчёты, гонки в памяти | чистый макет CSS |
| Integration | БД, очередь, файлы | нет I/O |
| Contract | меняется API/событие между частями | внутренний рефактор без схемы |
| E2E | критичный пользовательский путь | правка копирайта |

Негативные случаи, права, идемпотентность — если есть деньги, ПДн, роли, повтор запроса.

Evidence: команда + вывод. «В UI стало лучше» без запроса — не сдача для данных.

У каждой проверки различимы «ничего не произошло» и «всё хорошо»: скрипт-проверка assert'ит, что вообще сработала (подстановка состоялась, строка найдена); отчёт несёт exit code рядом с каждым выводом; ожидаемый непустой результат объявляется заранее — пустой ответ это провал, не успех.

Критерий приёмки выводится из способа сломаться, не из ожидаемого улучшения. Обязательный вопрос до формулировки: «как выглядит этот критерий, если правка сломана?» — совпадает с успехом → критерий негодный. Годные критерии различают состояния: «разброс значений существует», «ручка двигает результат» — а не «стало лучше».

Состояния, недостижимые на реальных данных, допустимо проверять через временную модификацию данных — с пометкой в отчёте: что менялось, как, оригинал восстановлен. Немаркированная модификация данных в evidence запрещена.

Суждение о правильности логики без сверки со спецификацией домена (если она существует) — суждение о согласованности кода с самим собой, не о правильности. Расхождение кода со спецификацией — находка в обе стороны: может врать код, может устареть спецификация; фиксируются оба варианта. Практика: построчный реестр сверки «спецификация ↔ код» (совпадает / расходится / не реализовано) — после него «в коде так» перестаёт быть аргументом.

Настройки: «читается» ≠ «работает». Проверка настройки — сквозной путь «изменил → увидел другой результат на наблюдаемом выходе, за известное время», включая уже посчитанное (см. производные данные в data.md). Настройка без наблюдаемого эффекта — мёртвая, это находка.

Находка класса «потеря или порча данных»: чтения кода недостаточно — либо воспроизведение, либо явная пометка «механизм подтверждён, масштаб не измерен» и прогон в очередь человека.

Тест проверяется мутацией: сломай проверяемое поведение на копии — тест обязан упасть; тест, проходящий всегда, — дефект, который не ловится ничем другим, а стоит минуты. Прогресс-инварианты (курсор, граница, окно, обязанные двигаться) проверяются последовательностью шагов с требованием движения на каждом — одиночная проверка «в допустимых границах» пропускает «застрял». Структурное свойство, не выражающееся в поведении (например, разбиение сборки), законно проверяется чтением исходника — с записанным обоснованием, почему поведением проверить нельзя.

# v1.6.0 — Независимое ревью, ограниченная критика и знания проекта

Редакция описывает, как команда агентов сохраняет исходную цель, проверяет её понимание и действует, когда повторные исправления не улучшают результат. Добавлены договоры аудита, мониторинга, знаний, передачи работы и владения ресурсами. Английская и русская версии обновляются вместе.

## Изменения

- **Независимая проверка смысла.** Для существенных или спорных требований проверяющий выводит ожидаемое поведение из первичного материала до знакомства с ожиданиями автора. Согласованные спецификация, код и тесты могут содержать общую ошибочную интерпретацию.
- **Ограниченная критика и пересмотр зацикленной работы.** По умолчанию — широкий независимый проход и целевая перепроверка. Два возврата без подтверждённого продвижения запускают ограниченное исследование проблемы и подхода. Смена модели и переименование задачи сохраняют историю; исчерпание предела не заменяет отсутствующие доказательства приёмки.
- **Прослеживаемые задачи и ревью.** Одна основная запись связывает закреплённые входы, версии кандидата, авторов, проверяющих, свидетельства, находки и неизменяемые вердикты. После значимых изменений пересматривается применимость ревью. Отмена и замена остаются явными исходами без поставки.
- **Знания проекта.** У профиля, проверенной памяти, спецификаций, решений, источников и состояния цикла разные обязанности. Память разделяет даты наблюдения, проверки и записи; текущие решения сверяют применимость с текущими фактами.
- **Навыки аудита и мониторинга.** `autoteam-audit` фиксирует охват рисков, находки и неизвестное. `autoteam-monitor` выводит настройки из контекста. Сравнение с опорным состоянием обнаруживает накопленное изменение, а договор доставки сохраняет неизвестный исход при потере подтверждения.
- **Координация и ресурсы.** Полезная работа автоматически делегируется в пределах доступных возможностей. Необязательный общий лимит включает потомков, повторы, ревью, сохранение и уборку. Восстановлению нужен независимый проверенный триггер либо явный предел ручного возобновления. Уборка следует доказательствам владения и активности.
- **Проверка полного комплекта.** Метаданные версии и скрипт без записи проверяют структуру, полноту локалей, обычные локальные ссылки и точный отпечаток содержимого. GitHub Actions настроен на проверку комплекта и регрессионные тесты в Linux и Windows.

Полный перечень, включая изоляцию QA, ROI, выбор стека и защиту рабочего дерева выкатки, — в [журнале изменений](../../CHANGELOG.md).

## Переход с 1.5

Сохраняй имеющиеся ID задач и историю. Добавляй недостающее происхождение по мере работы с записями; заполняй память только проверенными свидетельствами. На следующий цикл закрепи полный проверенный снимок: `canon.json`, входная документация, навыки, общие документы, шаблоны, соответствия локалей и скрипт проверки. Копии обнаружения обновляются явно; активный цикл сохраняет свой снимок.

Запусти `python scripts/check_canon.py` из корня комплекта. `--compare <bundle-root>` сверяет полную копию. Изменение исходников не заменяет глобальные установленные навыки и не устанавливает адаптеры среды.

## Проверки

Метод прошёл независимые смысловые ревью, десять заданных сценариев и отдельную пробу применения навыка. В Windows прошли 17 тестов скрипта; один тест настоящей символической ссылки пропущен из-за отсутствующих прав. Публичный workflow повторяет структурную проверку и регрессионные тесты; смысловая приёмка им не автоматизирована.

```text
python -X utf8 scripts/check_canon.py
python -X utf8 -m unittest discover -s tests -v
```

## Ограничения

Это библиотека метода в Markdown. Адаптеры планировщика, провайдеров, трекера, доставки и восстановления требуют реализации и проверки в целевой среде. Структурные проверки и сценарии не доказывают гарантии исполнения, спрос или измеренное улучшение бизнес-результатов. Проверка точной ревизии работающего релиза остаётся отложенной.

# autoteam 1.6 — Канон агентной разработки

Переносимая библиотека метода работы команды агентов: понять результат пользователя, спланировать, реализовать, независимо проверить и сохранить подтверждённые знания проекта. Метод применим к продуктам, исследованиям, экспериментам и документам. Работающий планировщик и подключения внешних провайдеров в комплект не входят.

Канонический язык — английский. [English](../README.md) и русская версия обновляются вместе. В библиотеке **25 навыков на каждом языке**. [Заметки к v1.6.0](docs/releases/v1.6.0.md) описывают изменения и переход, [журнал изменений](CHANGELOG.md) — историю редакций.

## Что нового в 1.6

- **Проверка результата и ограниченная критика.** Критический смысл независимо сверяется с первичными источниками. Два возврата без продвижения запускают пересмотр; смена модели не обнуляет историю. Открытая критика по умолчанию — широкий проход и целевая перепроверка. [Assurance](docs/process/assurance.md).
- **Прослеживаемая работа и ревью.** Одна запись задачи, закреплённые входы, все авторы, неизменяемые вердикты и их актуальная/устаревшая применимость. Отмена и замена — явные исходы без поставки. [Рабочие задачи](docs/process/work-items.md).
- **Повторно используемые знания проекта.** Разделены настройки, проверенная память, спецификации, решения, источники и состояние цикла. Текущая применимость сверяется с фактами и датами наблюдения. [Знания проекта](docs/process/project-knowledge.md).
- **Аудит и мониторинг.** Проверка применимых направлений риска и параметры наблюдения из контекста. Накопленный дрейф, неизвестная доставка и проверка реального расписания до обещания регулярности. [Аудит](skills/autoteam-audit/SKILL.md) и [мониторинг](skills/autoteam-monitor/SKILL.md).
- **Команда, лимиты и ресурсы.** Полезная работа делегируется автоматически, необязательные лимиты общие для всех агентов, доказательства сохраняются, убираются только собственные ресурсы. [Выбор моделей](docs/process/model-routing.md) и [жизненный цикл ресурсов](docs/process/resource-lifecycle.md).

## Быстрый старт

1. Скачай полный репозиторий или клонируй его:

   ```text
   git clone https://github.com/kochetovdv/autoteam.git
   cd autoteam
   python scripts/check_canon.py
   ```

   Проверке нужны Python 3 и его стандартная библиотека. Успех — `"ok": true` и отпечаток комплекта в результате.

2. Выбери английский или русский, сохрани проверенный снимок на цикл и передай агенту абсолютный путь к нему. [Стартовый текст](templates/kickoff.md) задаёт поручение, [профиль](templates/project-profile.md) — известные настройки проекта; агент заполняет их из контекста, а не просит человека заполнить каждое поле.
3. Для поручения укажи [оркестратор](skills/autoteam-orchestrator/SKILL.md), для выбора роли — [каталог](skills/autoteam-catalog/SKILL.md). Регистрируй навыки средствами своей агентной среды, сохраняя привязку общих ссылок к тому же снимку.

Установщик конкретного провайдера и готовые интеграции не входят в комплект. Одна скопированная папка навыка не является полной установкой. Перед обновлением проекта прочитай раздел об установке и закреплении версии ниже.

## Метод, проект и цикл

Канон определяет организацию работы. Профиль проекта — доменный словарь, стек, команды, доступные модели/интеграции, полномочия, лимиты и визуальные референсы. Проверенная память сохраняет факты и уроки с доказательствами. Спецификации задают желаемое поведение; решения сохраняют основания; state описывает текущий цикл. [Правила знаний](docs/process/project-knowledge.md) не позволяют им подменять друг друга.

Оркестратор сам запускает полезных агентов и независимые проверки без повторных просьб об их числе. Пользователь может задать лимит всей задачи; без него качество и завершение важнее экономии токенов. [Выбор моделей](docs/process/model-routing.md) описывает фактический запуск, общий учёт и резерв на сохранение/приёмку.

Критический смысл независимо сверяется с первичными источниками и наблюдениями. [Assurance](docs/process/assurance.md) ограничивает открытую критику и прерывает цепочки патчей без продвижения к исходной цели. Смена модели не обнуляет историю. Отменённая/заменённая работа отличается от принятой поставки; гарантии восстановления и мониторинга требуют проверенных возможностей среды.

Сначала объясняй последствия для пользователя и продукта, затем детали реализации. Различай готовность системы принимать оплату, наблюдаемую выручку и подтверждённую экономику.

## Установка и закрепление версии

Полный комплект — `canon.json`, входная документация, `skills/`, `docs/`, `templates/`, поддерживаемые соответствия `ru/` и `scripts/check_canon.py`. Сохрани полный неизменяемый снимок; зафиксируй версию, отпечаток, путь и язык в профиле/брифе проекта. Где среда позволяет, подключай навыки из этого снимка; иначе привяжи к нему копии обнаружения и общие ссылки.

Обязательные общие документы — зависимости. Одна скопированная папка навыка даёт локальное руководство, а не полный процесс. Проверяй комплект до подключения; не перезаписывай попутно глобальные навыки и не обновляй общую рабочую копию. Активный цикл читает свой снимок, даже если другой проект обновил источник. [Подробности комплекта](skills/README.md).

```text
python scripts/check_canon.py
python scripts/check_canon.py --compare <full-bundle-root>
```

Проверка показывает структуру, полноту локали, ссылки и различия содержимого. Она ничего не меняет и не устанавливает, не доказывает эквивалентность перевода или поведение агентов. Адаптеры среды должны реально запускать и проверять модели, наблюдения по расписанию, переходы трекера и восстановление.

## Проверки

Запускай проверку комплекта и её регрессионные тесты из корня репозитория:

```text
python -X utf8 scripts/check_canon.py
python -X utf8 -m unittest discover -s tests -v
```

GitHub Actions запускает обе команды в Linux и Windows. Структурные проверки и сценарный разбор инструкций не доказывают работу восстановления, гарантии доставки, соблюдение правил агентами или улучшение бизнес-результатов. [Границы проверки выпуска](docs/releases/v1.6.0.md).

## Границы

Ревью не изменяет свой предмет. Пишущие агенты используют изолированные рабочие области с владельцем. Внешние траты, обязательства, разрушение и production следуют выданным полномочиям. Аудит раскрывает неполноту охвата; монитор отличает отсутствие данных от отсутствия изменений и сам формирует внутренние настройки из контекста.

Библиотека поддерживается в `skills/`, `docs/` и `templates/`; команды и находки продукта остаются в продукте. [Сознательные пробелы](docs/process/gaps.md).

# Профиль проекта

Нормативные настройки проекта в пределах записанных полномочий. Используй существующие соглашения и документы; ссылайся вместо дублирования. Неизвестное остаётся неизвестным. Этот пустой шаблон и его заполнители — не факты о проекте. Метод: `docs/process/project-knowledge.md` в проверенном снимке канона цикла.

```markdown
Проект / репозиторий:
Ревизия профиля / владелец:
Ссылки на поручение и основания полномочий:
Язык человека / соглашения отчётности:
Существующие точки входа (README, текущее состояние, спецификация, решения, память, источники):
Санкционированные места вывода/записи и запрещённые действия:
Место результатов анализа без изменений репозитория, если применимо:

Стек / платформы / границы предметной области:
Настройка → значение → основание полномочий → ревизия / триггер пересмотра:
Наблюдения реализации, отличающиеся от этих настроек → evidence / расследование:

Команды (из какого каталога запускать):
Назначение → точная команда → ревизия источника → последняя фактическая проверка / результат:
Цель выкатки / граница разрешения / runbook:

Словарь предметной области:
Термин → определение → авторитетный источник / ревизия:

Соглашения артефактов / имена / статусы:
Ресурсы / указатели на хранилище секретов (без значений):
Коннекторы → назначение / область / указатель на учётку или среду / разрешённые действия:
Бюджеты и лимиты → единица / область / владелец / основание / действие при исчерпании:
Ссылка на политику выбора моделей:
Соглашения жизненного цикла ресурсов / хранения:
Триггеры перепроверки и зависимые документы:
```

Наблюдаемая конфигурация не становится санкционированной настройкой автоматически. Предлагай изменения профиля с соответствующим изменением и основанием полномочий; проверь их до признания нормативными. Профиль не ослабляет жёсткие стопы метода и не расширяет поручение пользователя. Текущая работа и блокеры остаются в состоянии цикла.

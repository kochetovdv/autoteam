# Реестр источников и повторное использование извлечения

По возможности используй существующий индекс источников. Индексируй материал, обосновывающий долговечные утверждения или дорогой в извлечении; маленькая задача может держать поля рядом с evidence. Все заполнители ниже — примеры полей, а не записи об источниках. Метод: `docs/process/project-knowledge.md` в проверенном снимке канона.

```markdown
ID источника / идентичность / расположение / область доступа:
Ревизия источника или хеш содержимого (алгоритм):
Когда получен / осмотрен:
Роль: наблюдение | желаемое поведение | санкционированный выбор | другое (пояснить)
Обработчик / версия / настройки извлечения / осмотренные страницы или диапазоны:
Покрытие вопросов → отвечено / частично / не исследовано:
Ограничения качества (OCR, таблицы, схемы, усечение, недоступный периметр):
Производные артефакты → место / ревизия / покрытые вопросы:
Зависимости → записи памяти / ссылки спецификации / решения / единицы работы:
Статус: suitable | incomplete | contradicted | changed / pending-recheck
Адресное перечитывание или повторная обработка → причина / периметр / владелец / результат:
```

Повторно используй пригодные производные артефакты для покрытых ими вопросов. Неизменный источник может потребовать адресного перечитывания из-за нового вопроса, плохого извлечения или противоречия. Не выводи отсутствие за пределами осмотренного периметра. Изменение источника или ненадёжное извлечение помечает зависимые утверждения к перепроверке; после расследования обнови покрытие и ссылки. При обновлении записи сохраняй ссылки на прежние ревизии.

Для хранилищ секретов фиксируй лишь безопасную идентичность источника и ограничение доступа; никогда не извлекай, не хешируй, не копируй и не архивируй сырые значения секретов ради реестра. Сводка без прослеживаемого первичного evidence не устанавливает факт и не санкционирует настройку.

# Ресурсы и жизненный цикл запуска

Учётки, доступы, среды, данные и действия человека, а также ресурсы, созданные или заимствованные запуском. Деньги — `autoteam-budget`. Значения секретов никогда не попадают в этот файл, снимки и архивы; только указатели на хранилище. Используй существующий журнал проекта. Метод: `docs/process/resource-lifecycle.md` в проверенном снимке канона. Строки ниже — незаполненные примеры, а не реальные ресурсы.

| ID | Тип / идентичность ресурса | Статус | Владелец / указатель доступа | Срок / лимит | Зависимая работа |
|---|---|---|---|---|---|
| R-<id> | учётка / доступ / среда / данные / действие человека | есть / нужно / запрошено (дата) | | | |

Для каждого принадлежащего запуску или заимствованного ресурса включи эти поля в тот же журнал либо его единицу работы; не веди дублирующие реестры:

```markdown
Запуск / единица работы / владелец:
Точная идентичность (абсолютный путь дерева, ID процесса/сессии, контейнер, том, порт и т. п.):
Владение: создан / делегирован / заимствован (владелец и разрешение):
Назначение / разрешённые действия:
Статус: planned | active | outcome-unknown | cleanup_pending | cleaned | retained | transferred
Токен владельца блокировки / heartbeat / evidence активности, если применимо:
Сохранить до уборки → безопасные изменения / evidence / нужные игнорируемые файлы / проверенный указатель восстановления:
Правило уборки или хранения → действие / владелец / триггер или срок:
Последняя сверка / фактический исход / ошибка / следующее действие:
```

- Фиксируй точные ID до зависимого использования. Неизвестный исход создания требует сверки до повтора. Один писатель на изолированное физическое дерево; назначения файлов недостаточно. Передача владения внутри санкционированной задачи — явное действие координатора; конфликт с посторонним владельцем — человеку.
- Сверяй при завершении **и** при сбое/восстановлении. До удаления сохрани восстанавливаемые изменения и нужное очищенное evidence. Архивировать можно лишь собственные worktree с восстанавливаемыми снимками; нужные игнорируемые файлы сохраняй отдельно. Исключи сырые секреты из массовых операций.
- Уборка заново проверяет владельца и разрешённый путь цели. Никакого слепого prune, удаления общих томов или удаления по возрасту. Возраст блокировки запускает проверку активности; неизвестная активность блокирует второго писателя. Только подтверждённое отсутствие позволяет условное атомарное восстановление блокировки.
- Неудачная уборка остаётся `cleanup_pending` в состоянии и передаче с владельцем и следующей проверкой. Сохраняемым ресурсам нужны явные причина, владелец и условие удаления. Действия мониторов используют тот же жизненный цикл.
- Расхождение реестра останавливает только работу, опирающуюся на запись, до исправления записи либо реальности. Недостающий ресурс блокирует свои зависимости. Действия только человека идут в его очередь с конкретным последствием; распределение общего лимита требует решения уполномоченного владельца. Срок проверяется на приёмке.
- Недоступный источник/инструмент/выгрузка — открытое ограничение периметра с владельцем, затронутыми выводами и триггером перепроверки. Проверяй на относящихся к нему чекпойнтах и после восстановления. Пиши «в этом периметре не искали», не «отсутствует». Закрывай ревизией зависимых выводов; неразрешённые ограничения входят в передачу. Агент не вправе молча сужать поручение.

# Product stack

The current product owns its stack and client lineup.

1. Existing lockfiles, ADRs, and explicit project decisions are the starting point. Changing a live product's stack requires the applicable authority; do not silently replace it.
2. No stack in **interactive mode**: ask one consequential question and stop only work that depends on the choice.
3. No stack in **solution mode**: choose the minimum sufficient stack for the agreed outcome, including the required visual/interaction level, record alternatives and assumptions, and continue. The same rule applies to UI and delivery roles; do not turn the missing stack into a repeated questionnaire.
4. New client platforms (web/responsive/PWA/native) are explicit scope decisions with their cost. Do not silently add one.
5. Language/framework craft belongs in the project profile/overlay. Universal correctness and boundary rules are applied in the product's language.

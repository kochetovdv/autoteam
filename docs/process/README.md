# Process authorities

Each rule has one detailed home; role skills retain the essentials and link here.

- [Orchestration](orchestration.md): authority, automatic team, human communication, initiative, and handoff.
- [Work items](work-items.md): task transitions, authors, revisions, review history/applicability, and flow.
- [Project knowledge](project-knowledge.md): profile, verified memory, specification, source registry, and pinned canon.
- [Assurance](assurance.md): audit coverage, independent meaning, bounded critique and stalled-loop reassessment.
- [Monitoring](monitoring.md): agent-generated observation settings, significant changes, and actual scheduling.
- [Resource lifecycle](resource-lifecycle.md): ownership, cycle locks, checkpoint preservation, and cleanup.
- [Model routing](model-routing.md): capability-based dispatch and optional shared task limits.
- [Stack](stack.md): the mode-aware stack decision.
- [Gaps](gaps.md): deliberate boundaries and deferred work.

Delivery craft lives in [delivery](../delivery/README.md), documentation practice in [docs practice](../docs-practice/README.md), and privacy in [privacy](../compliance/privacy.md). These rules specify a method; scheduler/provider/tracker adapters must be implemented and verified in the actual environment.

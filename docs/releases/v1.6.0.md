# v1.6.0 — Independent review, bounded critique, and project knowledge

This release defines how an agent team preserves the original goal, checks its interpretation, and responds when repeated fixes do not improve the outcome. It adds contracts for audits, monitoring, knowledge, handoffs, and resource ownership. English and Russian versions are maintained together.

## Changes

- **Independent meaning checks.** For consequential or disputed requirements, a reviewer derives expected behavior from primary material before seeing the author's derived expectations. Agreement between a specification, code, and tests can share the same mistaken interpretation.
- **Bounded critique and stalled-work reassessment.** The default is one broad independent pass and one targeted recheck. Two correction returns without demonstrated outcome progress trigger a bounded investigation of the problem and approach. Model changes and task renaming preserve the history; reaching a limit does not supply missing acceptance evidence.
- **Traceable work and reviews.** One authoritative work item links pinned inputs, candidate versions, contributors, reviewers, evidence, findings, and immutable verdicts. Review applicability is reassessed after relevant changes. Cancelled and superseded work remain explicit non-delivery outcomes.
- **Project knowledge.** Profile, verified memory, specifications, decisions, sources, and cycle state have separate responsibilities. Memory distinguishes observation, verification, and recording dates; current decisions check applicability against current facts.
- **Audit and monitoring skills.** `autoteam-audit` records risk coverage, findings, and unknowns. `autoteam-monitor` generates settings from context. Reference-state comparisons expose cumulative change, while delivery protocols preserve unknown outcomes after a lost acknowledgement.
- **Coordination and resources.** Useful agents are delegated automatically within available capabilities. Optional whole-task limits include descendants, retries, review, preservation, and cleanup. Recovery requires an independent verified trigger or a disclosed manual-resume limit. Resource cleanup follows ownership and liveness evidence.
- **Complete-bundle validation.** Version metadata and a read-only checker validate structure, locale coverage, common local links, and exact content fingerprints. GitHub Actions is configured to run the checker and its regression tests on Linux and Windows.

See the [changelog](../../CHANGELOG.md) for the complete change inventory, including QA isolation, ROI, stack-selection, and release-workspace corrections.

## Upgrade from 1.5

Keep existing work-item identifiers and history. Add missing provenance as records are touched; initialize memory only from checked evidence. For the next cycle, pin a complete verified snapshot containing `canon.json`, entry documentation, skills, shared docs, templates, locale counterparts, and the checker. Update existing discovery copies explicitly; retain an active cycle's pinned snapshot.

Run `python scripts/check_canon.py` from the bundle root. Use `--compare <bundle-root>` to verify a complete copy. This source update does not replace global installed skills or install environment adapters.

## Validation

The method revision received independent semantic reviews, ten specified tabletop scenarios, and a separate skill-application trial. The checker test suite passed 17 tests on Windows; one real-symlink test was skipped because the required privilege was unavailable. The public workflow repeats structural validation and regression tests; it does not automate semantic acceptance.

```text
python -X utf8 scripts/check_canon.py
python -X utf8 -m unittest discover -s tests -v
```

## Limitations

This is a Markdown method library. Scheduler, provider, tracker, delivery, and recovery adapters require implementation and testing in the target environment. Structural checks and scenario reviews do not establish runtime guarantees, customer demand, or measured business improvements. Exact deployed-release revision verification remains deferred.

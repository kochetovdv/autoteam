# React: ремесло

Читай этот файл, **если UI продукта на React (веб)**. Не назначай React, если в репозитории другой UI-стек (`docs/process/stack.md`). Мобильный клиент не подключай «заодно».

## Структура

- Один продукт — один `src/` с границами по экранам/доменам, не по типу файла в одну кучу на 50 «components».
- Состояние сервера (списки, карточки) не дублируй в глобальном сторе без нужды.
- CSS: токены проекта (`var(--*)`). Новые hex только с записью в токены.
- UI-kit (shadcn и т.п.) — только если проект уже на нём **и** токены переопределены. Демка kit ≠ дизайн продукта. См. `docs/design/anti-slop.md`.

## URL как источник фильтров

Период, выбранный объект, вкладка — в адресе (query или hash — как в проекте). Обновление фильтра меняет URL; Back возвращает то же состояние. Исключение — задокументируй.

## Состояния экрана

Пусто, загрузка, ошибка, мало данных, много данных. Сортировка и фильтр либо работают, либо явно выключены — без ложной иконки.

## Тесты

- Сложные правила формата и прав — unit.
- Критичный сценарий (логин, оплата, смена роли) — e2e по делу, не на каждый отступ.
- `tsc` / сборка зелёные перед сдачей.

## a11y минимум

Видимый фокус, `type="button"` в формах, контраст, не информация одним цветом, подписи полей.

## Мобильный клиент (не default)

Нет требования — только адаптив веба, если он нужен. Есть требование — явно выбери и оцени:

| Вариант | Когда |
|---------|--------|
| Адаптив веба | те же сценарии на телефоне, офлайн не критичен |
| PWA | «иконка на дом», слабый офлайн, без сторов |
| Кроссплатформа (например React Native) | одна команда, нативные сторы, не тяжёлая платформенная логика |
| Native (Swift/Kotlin) | платформенные API, жёсткий UX стора, бюджет на две команды |

Цена (сторы, пуши, ревью Apple/Google) — в оценке отдельной строкой. Не делай вид, что «ещё один npm».

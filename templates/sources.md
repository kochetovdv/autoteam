# Source registry and reusable extraction

Use an existing source index where possible. Index material supporting durable claims or costly extraction; a tiny task can keep these fields with its evidence. All placeholders below are examples of fields, not source records. Method: `docs/process/project-knowledge.md` in the verified canon snapshot.

```markdown
Source ID / identity / location / access scope:
Source revision or content hash (algorithm):
Retrieved / inspected at:
Role: observation | desired behavior | authorized choice | other (explain)
Processor / version / extraction settings / inspected pages or ranges:
Question coverage → answered / partial / unexamined:
Quality limits (OCR, tables, diagrams, truncation, unavailable scope):
Derived artifacts → location / revision / covered questions:
Dependents → memory entries / spec references / decisions / work items:
Status: suitable | incomplete | contradicted | changed / pending-recheck
Targeted reread or reprocessing → reason / scope / owner / outcome:
```

Reuse suitable derived artifacts for the questions they cover. An unchanged source can require a targeted reread for a new question, poor extraction or contradiction. Do not infer absence outside inspected scope. A changed source or unreliable extraction marks dependent claims pending recheck; update coverage and links after investigation. Preserve earlier revision references when updating the record.

Record only a safe source identity and access limitation for secret stores; never extract, hash, copy or archive raw secret values for this registry. A summary without traceable primary evidence does not establish a fact or authorize a setting.
